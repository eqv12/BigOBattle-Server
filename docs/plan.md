# EMERGENT Build Plan (Living Document)

Last updated: 2026-03-21

## Goal
Build a stable, room-first, multi-game-capable LAN coding game platform where users submit bots and compete on room-scoped leaderboards.

---

## Product Decisions Locked
- Room-only ratings (no global leaderboard yet).
- Minimal authentication:
  - Admin creates room -> server returns `room_code` + admin password.
  - Participant joins with `room_code` + display name.
  - First submit for `(room, display_name)` sets password.
  - Re-submit requires same password.
- Game is selected by room creator at room creation.
- Matchmaking should be simple/pragmatic (not production-hard).
- Stabilization quality is preferred over shipping speed.
- Keep Flask for this refactor cycle; reassess FastAPI migration later.
- Frontend UI will be rebuilt in React with Monaco editor workspace.
- Room creation uses autogenerated room code and admin 4-digit PIN.
- Editor/workspace must be language-agnostic (Python, Java, C).

## Target Data Model (Room First)
### tables
1. `rooms`
   - `id`
   - `room_code` (unique)
   - `admin_password_hash`
   - `game_key`
   - `created_at`
   - `status`

2. `participants`
   - `id`
   - `room_id`
   - `display_name`
   - `password_hash`
   - `active_bot_path`
   - `created_at`
   - `last_submission_at`
   - unique `(room_id, display_name)`

3. `room_ratings`
   - `id`
   - `room_id`
   - `participant_id`
   - `rating`
   - `rd`
   - `vol`
   - `matches_played`
   - `last_played_at`
   - unique `(room_id, participant_id)`

4. `room_matches`
   - `id`
   - `room_id`
   - `game_key`
   - `participant_a_id`
   - `participant_b_id`
   - `winner_participant_id` (nullable for draw)
   - `replay_data`
   - `termination_reason`
   - `played_at`

## API Plan (MVP)
1. `POST /api/rooms`
   - input: `{ game_key }`
   - output: `{ room_code, admin_password }`

2. `POST /api/rooms/{room_code}/join`
   - input: `{ display_name }`
   - output: `{ participant_id }`

3. `POST /api/rooms/{room_code}/submit` (multipart)
   - fields: `display_name`, `password`, `bot_zip_file`
   - behavior:
     - if first submit: set password hash
     - else verify password hash

4. `GET /api/rooms/{room_code}/leaderboard`
   - output: ranked participants in that room

5. `GET /api/rooms/{room_code}/matches/recent`
   - output: recent room matches

6. (optional) `POST /api/rooms/{room_code}/test`
   - unranked test match
